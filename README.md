# BitVault — библиотека битов

Локальное веб-приложение для хранения и прослушивания битов из FL Studio.
Без аккаунта всё лежит в браузере (IndexedDB): аудио, обложки, `.flp` и
метаданные никуда не отправляются. Вход через Google открывает библиотеку
аккаунта — треки и файлы хранятся на сервере и доступны на любом устройстве;
перенос локальных треков запускается вручную (см. раздел «Аккаунт»).

## Как запустить

Готовый сайт уже опубликован — устанавливать и запускать ничего не нужно:

1. Откройте **https://paluuwp.github.io/bitvault/** в Chrome, Edge, Firefox
   или Safari.
2. Нажмите «Добавить биты» и выберите аудиофайлы (mp3, wav, ogg, flac и др.)
   или проекты `.flp` — их также можно перетащить в окно.
3. Заполните название (BPM, жанр и теги — по желанию) — бит появится
   в библиотеке.

Без входа в аккаунт библиотека хранится в браузере (IndexedDB): аудио,
обложки и метаданные на сервер не отправляются, у каждого человека она своя.
Вход через Google включает библиотеку аккаунта — см. раздел «Аккаунт».
Приложение можно установить на компьютер или телефон и открывать офлайн —
см. раздел «Установка как приложение (PWA)».

**Локальный запуск из исходников.** Нужен Node.js 20.19+:

```bash
npm install
npm run dev
```

Затем откройте `http://localhost:5173/`. Остальные команды — в разделе
«Команды».

## Возможности

- Загрузка аудио (mp3, wav, ogg, flac и др.) и файлов проектов `.flp`
  перетаскиванием или через кнопку «Добавить биты».
- Библиотека в виде сетки или списка: название, BPM, тональность, жанр, теги,
  заметки, обложка, цвет, избранное, дата, длительность, число прослушиваний.
- Переименование и редактирование любого бита, удаление с подтверждением.
- Поиск по названию/жанру/тегу, фильтр по тегу и избранному,
  сортировка по дате, названию, BPM и последнему прослушиванию.
- Встроенный плеер: play/pause, перемотка, громкость, следующий/предыдущий,
  пробел как play/pause.
- Экспорт и импорт всей библиотеки одним ZIP-архивом.
- Индикатор занятого места и запрос постоянного хранения.
- Тёмный интерфейс в духе FL Studio: графитовые панели, оранжевый акцент,
  LED-индикаторы, моноширинные счётчики BPM и времени; адаптивность,
  управление с клавиатуры.
- Устанавливается как приложение (PWA) и работает офлайн; новая версия
  предлагается плашкой «Обновить», без принудительной перезагрузки.

## Стек

Vite 7, React 19, TypeScript 5.9, Tailwind CSS 4, IndexedDB через `idb`,
ZIP через `fflate`, Vitest + Testing Library.

## Установка как приложение (PWA)

Приложение собирается как PWA: его можно установить на компьютер или телефон,
и после первого открытия оно работает офлайн — без интернета и без запуска
чего-либо на вашем компьютере. Без входа в аккаунт библиотека по-прежнему
хранится локально в браузере, у каждого человека она своя.

- **Chrome / Edge на компьютере:** значок «Установить» в адресной строке или
  меню ⋮ → «Установить приложение». После установки BitVault открывается в
  отдельном окне без адресной строки.
- **Android:** меню браузера → «Установить приложение» / «Добавить на главный
  экран».
- **iPhone / iPad (Safari):** кнопка «Поделиться» → «На экран “Домой”». iOS
  открывает PWA в отдельном окне, но без установки офлайн-режим ограничен —
  добавляйте на домашний экран.

### Обновления

При каждом деплое выходит новая версия. Приложение проверяет её при запуске и
при возврате на вкладку; когда обновление готово, сверху появляется плашка
«Доступна новая версия BitVault». Нажмите «Обновить» — страница перезагрузится,
библиотека и файлы останутся на месте. Пока идёт загрузка, импорт или экспорт,
кнопка «Обновить» заблокирована, чтобы не прервать операцию. «Позже» скрывает
плашку; она появится снова при следующем запуске или когда выйдет следующая
версия.

Удаление ярлыка приложения данные не стирает: библиотека живёт в хранилище
браузера, а не в ярлыке. Но «Очистить данные сайта» в браузере удалит всё —
регулярно сохраняйте ZIP-копию через «Настройки» → «Экспортировать
библиотеку».

## Аккаунт

Вход через Google — необязательный: без него библиотека работает как раньше.
Кнопка входа находится в левом меню, над «Настройки» (на телефоне — в меню,
которое открывается кнопкой в шапке).

- **Зачем.** Вход открывает библиотеку аккаунта: треки и файлы хранятся на
  сервере и доступны после входа на любом устройстве.
- **Что происходит после входа.** В списке появляются треки аккаунта (они
  помечены как облачные); новые биты, добавленные при активном входе,
  загружаются на сервер вместе с аудио, обложкой и вложениями. Правки и
  удаление облачных треков сразу уходят на сервер.
- **Перенос старых треков.** Треки, созданные до входа, остаются локальными.
  Над библиотекой появляется баннер «Перенести треки в аккаунт» — он
  загружает их на сервер по одному, с прогрессом; отменить перенос можно,
  просто не нажимая кнопку.
- **Файлы.** Аудио и обложки не скачиваются заранее: браузер получает
  подписанную ссылку на сервер и стримит файл (с поддержкой перемотки).
  Скачанные файлы и метаданные кэшируются в браузере, поэтому список
  библиотеки открывается и без сети. Экспорт библиотеки перед сборкой ZIP
  докачивает недостающие файлы аккаунта — резервная копия остаётся полной
  (для этого нужна сеть: если файл ещё не скачан и сервер недоступен,
  экспорт прервётся).
- **Счётчик прослушиваний.** Пока хранится на устройстве и не синхронизируется:
  серверное обновление его не затирает, но на другом устройстве статистика
  начнётся заново (серверный эндпоинт прослушиваний — в планах).
- **Выход.** «Выйти» в диалоге аккаунта удаляет сессию и облачный кэш с
  устройства; локальные треки остаются. «Выйти на всех устройствах»
  дополнительно отзывает остальные сессии.
- **Кому можно.** Только адресам из списка доступа на сервере. Другим аккаунтам
  Google вход вернёт «Этот аккаунт не разрешён», библиотека продолжит работать.
- **Что хранится.** Сервер создаёт сессию на 30 дней и продлевает её при
  использовании (не чаще раза в сутки); актуальный срок приходит при обновлении
  данных аккаунта. Токен хранится в хранилище браузера (ключ `bv.auth.session`).
  Вход восстановится после перезагрузки.
- **Сеть.** При запуске приложения запросов к Google нет: кнопка Google
  загружается только при открытии диалога аккаунта. Список треков
  аккаунта обновляется при загрузке библиотеки; если сервер недоступен,
  показывается кэш.
- **Локальная разработка.** Публичные значения по умолчанию уже вписаны;
  переопределить их можно через `VITE_API_URL` и `VITE_GOOGLE_CLIENT_ID`
  (см. `.env.example`). Google-вход на локальном сервере работает только по
  адресу `http://localhost:5173` — при занятом порте запускайте
  `npm run dev -- --port 5173 --strictPort`.

## Ограничения

- `.flp` хранится как вложение: браузер не умеет его воспроизводить или
  разбирать, поэтому карточка проекта доступна для скачивания.
- BPM и тональность вводятся вручную, автоопределения нет.
- Файлы больше ~90 МиБ на сервер не загружаются (ограничение тела запроса
  Worker); докачка частями — в планах.
- Квота браузера ограничена; приложение предупреждает о заполнении хранилища.
  Регулярно делайте экспорт библиотеки как резервную копию.
- Один архив импорта ограничен 10 000 треков и 2 ГБ файлов (до 50 вложений на
  трек); записи вне каталога `files/` не распаковываются, а импорт блокируется,
  пока идёт загрузка новых файлов. Экспорт откажется создавать архив, который
  сам не сможет импортировать, — удалите лишние файлы перед резервной копией.
- Основные браузеры — Chrome и Edge; Firefox и Safari поддерживаются по мере
  возможностей (Safari может вытеснять данные неактивных сайтов).
- Service worker регистрируется относительно папки приложения, поэтому
  открывайте BitVault по адресу развёртывания (`https://…/bitvault/`), а не по
  вложенному пути вида `/bitvault/a/b` — там офлайн-режим не активируется.

## Приватность

Приложение по умолчанию не обращается к сторонним сервисам: шрифты и все
ресурсы лежат в сборке, файлы битов не покидают устройство. Сетевые запросы
к самому приложению и его service worker нужны для установки и обновлений PWA.

Исключение — необязательный вход через Google: скрипт Google Identity Services
загружается только при открытии диалога аккаунта, а на сервер входа уходят
лишь данные Google-токена. Без входа сами биты, обложки и `.flp` на сервер не
отправляются. Если вы вошли в аккаунт, треки и их файлы загружаются в
библиотеку аккаунта на сервере (приватное хранилище R2) — иначе они не были бы
доступны на других устройствах. API-ключей и секретов в клиентской сборке нет.
